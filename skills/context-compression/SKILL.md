# Context Compression: 文脈圧縮 & トークン最適化プロトコル

## 1. 概要と目的
本スキルは、長時間の開発セッションやマルチターンのリサーチ・コード改修において、**「コンテキストウィンドウの過度な膨張（トークン爆増）を防ぎつつ、重要な前提・命令・環境制約を見失わない」** ための文脈制御プロトコルです。

Headroomエンジンおよびセマンティック要約技術と連携し、トークンコスト削減とLLMの応答速度向上（レイテンシ半減）を実現します。

---

## 2. 圧縮・保護の優先順位階層 (Priority Levels)

```text
[最優先・絶対保護] 1. システムプロンプト, ユーザールール (AGENTS.md), 現行タスクのGoal
      │
[高優先・保持]     2. 直近3ターンのツール実行結果, 設定ファイル (.env, config)
      │
[中優先・要約圧縮] 3. 過去の会話ターン, 巨大なファイル参照結果 (read_file / search_web)
      │
[低優先・パージ]   4. 重複したエラー出力, 不要になったログファイルの中間文字列
```

---

## 3. 圧縮実行プロトコル

### 1. ログ・コードデータのHeadroomセマンティック圧縮
- `read_file`, `exec_command`, `search_web` 等で数千行を超える巨大テキストを取得した際、無加工でコンテキストに保持せず、必要な部分構造（スタックトレース、定義箇所、重要数値）をスマート抽出し、テキスト長を50%〜90%削減。

### 2. マルチターン履歴のセマンティックサマリー化
- 10ターン以上の対話が累積した場合、完了した中間ステップの思考・出力を「決定事項と変更点の要約メモ」に書き換えて過去履歴を軽量化。

### 3. 未定義・重複データの自動パージ
- 同一コマンドの重複実行ログや失敗ログのテキストを自動的に最新の実行結果に統合。

---

## 4. 効果とメリット
- **トークン消費量の最大85%削減**: 90Kトークン等の不必要な膨張を根本からカット。
- **コンテキスト品質の純粋化**: LLMが指示や制約を見失う「迷子状態（Lost in the Middle）」を物理的に回避。
