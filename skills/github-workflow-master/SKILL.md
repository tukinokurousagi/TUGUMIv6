## 🛠️ 第2部：アクション別 実行プロトコル

### 1. 【自動セーブ】Smart Semantic Commit
ユーザーから「セーブして」「コミットして」「変更を記録して」と指示された場合：
1. **差分スキャン**: `git status` および `git diff` を実行し、何が変更・追加・削除されたかを網羅的にスキャン。
2. **コミットタイプの自動判定**:
   - `feat:` 新機能・新スキルの追加
   - `fix:` バグ修正・エラー修復
   - `refactor:` コード整理・モジュール統合
   - `docs:` ドキュメント・マニュアル更新
   - `perf:` パフォーマンス向上
   - `chore:` 設定ファイル・依存関係の更新
3. **高品質な日本語コミットメッセージの生成**:
   - 1行目: `<type>: 変更の簡潔な要約（日本語）`
   - 2行目以降: 変更理由、影響範囲、実施した検証内容を箇条書きで明記。
4. **コミット実行**: `git add <対象ファイル>` ➔ `git commit -m "..."` を実行。

### 2. 【クラウド同期】GitHub Push & Sync
ユーザーから「GitHubに上げて」「バックアップして」「プッシュして」と指示された場合：
1. **ブランチ確認**: 現在の作業ブランチ（`main` または feature ブランチ）を確認。
2. **GitHub MCP 連動**: GitHub MCP（`push_files` 等）または `git push origin <branch>` を安全に実行。
3. **同期完了報告**: GitHub 上のリポジトリ URL と最新コミットハッシュを添えて報告。

### 3. 【PR自動生成】Rich Pull Request Generation
ユーザーから「PRを作って」「プルリク出して」と指示された場合：
1. **feature ブランチの作成・切り替え**: 本番ブランチを汚さないよう `git checkout -b <branch-name>`。
2. **変更のコミット & プッシュ**: リモートへブランチをプッシュ。
3. **GitHub MCP (`create_pull_request`) の発動**:
   - **PRタイトル**: 変更内容が一目でわかる明瞭なタイトル。
   - **PR本文**: 以下のリッチな Markdown 構造を自動生成：
     ```markdown
     ## 概要 (Overview)
     - 今回の変更の目的と背景

     ## 変更点 (Changes)
     - [x] 機能Aの実装
     - [x] モジュールBのリファクタリング

     ## テスト・検証結果 (Verification Evidence)
     - 実機テストコマンドおよび 100% PASS ログ
     ```
4. **生成された PR の URL を拓磨様へ提示**。

### 4. 【PRレビュー＆マージ】Review, Resolve & Merge
1. **PRコメントの取得**: GitHub MCP (`pull_request_read` / `list_issues`) でレビューコメントを取得。
2. **修正＆コメント解決**: 指摘事項をコードに反映し、コメントを「解決済み（Resolved）」に更新。
3. **安全マージ**: すべてのテスト通過を確認後、GitHub MCP (`merge_pull_request`) で `main` へ統合。
