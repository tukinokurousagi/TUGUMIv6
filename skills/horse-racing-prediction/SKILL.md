# Horse Racing Self-Improving Professional Prediction Skill (v2.0)

## Overview
Perform professional Japanese horse-race analysis from dynamic natural-language requests such as:
- 「今日の小倉10Rを予想して」
- 「8月16日の札幌11Rを予想して」
- 「〇〇記念を予想して」

> [!IMPORTANT]
> **Dynamic Parameter Rule**: Race date, venue, race number, and race name ARE NOT fixed or hardcoded. All parameters MUST be dynamically resolved from the user request.

> [!TIP]
> **Continuous Self-Learning Engine**: This skill dynamically loads past learnings (`references/learned-biases.md`) and updates factor weights after race results are confirmed via `mcp_horse_racing_race_learn`.

---

## 1. Core Operating Rules

### Rule 1 — Factual Layer vs Analysis Layer
- **Factual Layer** (Retrieved via MCP only): date, venue, race_number, race_name, course, distance, runners, odds, history.
- **Analysis Layer** (Generated by reasoning + learned weights): pace scenario, tactical position, relative ability, probability estimates, prediction marks, betting tickets.

### Rule 2 — Horse Identification & Format Requirement
Every horse in prediction marks, analysis, and betting tickets MUST strictly follow the format:
`『[馬番号] 馬名』` (e.g., `『[7] サンプルホース』`)
Never output a horse number without its verified horse name.

---

## 2. Self-Improving Dynamic Pipeline

```
USER REQUEST
    ↓
1. Parse Intent (Date, Venue, Race Number, Race Name dynamically)
    ↓
2. Load Learned Biases & Factor Weights (references/learned-biases.md)
    ↓
3. Call mcp_horse_racing_race_resolve & race_card
    ↓
4. Call mcp_horse_racing_validate (Check field integrity)
    ↓
5. Call mcp_horse_racing_horse_history / race_context / market
    ↓
6. Apply Tuned Probability Weightings & Assign Prediction Marks
    ↓
7. Betting Ticket Construction & Call mcp_horse_racing_validate with tickets
    ↓
8. Generate Markdown Report & Call mcp_horse_racing_report_save
    ↓
9. [Post-Race Retrospective] Call mcp_horse_racing_race_learn to auto-tune model weights!
```

---

## 3. Mandatory Validation Rules

Before finalizing the report:
1. `race_resolve` status MUST be `confirmed`.
2. `race_card` MUST be validated with `mcp_horse_racing_validate`.
3. If `validation_status == "FAIL"`, STOP immediately and inform the user. DO NOT GUESS.
4. All tickets MUST pass horse number/name cross-checking.

---

## 4. Report & Persistence Rules

- **Filename Standard**: `YYYYMMDD_{開催地}{レース番号}R_{レース名}_予想レポート.md`
- **Target Directory**: `/storage/emulated/0/TUGUMIDesk/競馬予想/`
