# System Prompt Architect v2 (`system-prompt-architect`)

## Overview

Generate production-ready, deeply characterized system prompts and persona definitions for any AI agent or LLM. Transform vague user requests into **9-layer XML-delimited behavioral contracts** equipped with:

- **Deep Persona Psychology** — Big Five personality traits, emotional response profiles, cognitive styles
- **Composable Identity Pipeline** — Stable Backbone + Dynamic Memory + Retrieval Policies
- **Chain-of-Verification** — Fact-checking protocol for high-risk domains (medical, legal, financial)
- **20+ Professional Domain Patterns** — Pre-built expert persona templates spanning diverse industries

> **Design Decision**: Anti-jailbreak / Anti-breakthrough defense layers are **intentionally excluded** from this skill. This enables research into persona behavioral drift, output variation under adversarial conditions, and character consistency analysis.

## When to Use

### Triggering Conditions
- User asks to "create a system prompt" or "build an AI agent" for a specific domain
- Need to define a deeply characterized professional persona with consistent behavior
- User gives a brief or vague request (e.g., "Make an agent that predicts horse races" or "Create a cybersecurity expert")
- Need to generate persona definitions optimized for specific LLM architectures (local vs cloud)
- Research into persona stability, drift patterns, or behavioral consistency under various conditions

## The 9-Layer Bento-Box Architecture

Every system prompt generated by this skill follows the 2026 9-Layer Bento-Box Architecture with **Sandwich Reinforcement**:

```xml
<system_prompt>
  <identity_and_persona>              <!-- L1: Role, expertise, stance, tone, vocabulary -->
  <objective_and_scope>               <!-- L2: Primary goal, responsibilities, boundaries -->
  <reasoning_framework>               <!-- L3: Hidden CoT, cognitive style, fallback logic -->
  <operational_constraints>           <!-- L4: Identity persistence & anti-hallucination -->
  <meta_cognition_control>            <!-- L5: Configurable: CONCEAL / TRANSPARENT / RESEARCH -->
  <chain_of_verification>             <!-- L6: Fact-checking for high-risk domains -->
  <emotional_behavioral_profile>      <!-- L7: Big Five traits, stress response, interpersonal style -->
  <output_contract>                   <!-- L8: Format, structure, quality standards -->
  <few_shot_examples>                 <!-- L9: Normal + Edge-Case examples -->

  <persona_reinforcement_anchor>      <!-- SANDWICH TAIL: Final immutable role lock -->
</system_prompt>
```

### Layer Descriptions

| Layer | Name | Purpose |
|:---|:---|:---|
| L1 | Identity & Persona | Role title, experience level, expertise domains, communication tone, vocabulary level, first-person reference |
| L2 | Objective & Scope | Primary goal, key responsibilities, allowed/disallowed scope boundaries |
| L3 | Reasoning Framework | Domain-specific CoT steps, cognitive style (analytical/intuitive/practical/theoretical), fallback strategies |
| L4 | Operational Constraints | Identity persistence rules, anti-hallucination rules, behavioral prohibitions, off-target prevention |
| L5 | Meta-Cognition Control | **Configurable mode**: CONCEAL (hide meta-reasoning), TRANSPARENT (allow when relevant), RESEARCH (full transparency for analysis) |
| L6 | Chain-of-Verification | Fact-checking protocol with risk level (LOW/MEDIUM/HIGH/CRITICAL). Essential for medical, legal, financial domains |
| L7 | Emotional & Behavioral Profile | Big Five personality scores (0-100), stress response pattern, communication quirks, interpersonal style |
| L8 | Output Contract | Format specification, structure schema, quality checklist, output language |
| L9 | Few-Shot Examples | Normal response examples + edge-case examples demonstrating persona-consistent handling of difficult situations |
| Tail | Persona Reinforcement Anchor | Sandwich Tail: final immutable directive reinforcing role persistence |

## Core Generation Protocol

When asked to generate a system prompt, follow this **6-step execution protocol**:

### Step 1: Persona Interview (対話的ヒアリング)

If the user's request is vague or underspecified, conduct a structured interview using the [persona_interview_protocol.md](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/templates/persona_interview_protocol.md).

**Phase 1 — Essential Questions (3 questions):**
1. Purpose & Audience — Who is this agent for and what does it accomplish?
2. Character Profile — What kind of person would this agent be?
3. Deployment Target — Which LLM will this prompt be used with?

**Phase 2 — Deep Dive (Optional, up to 5 additional questions):**
4. Hard constraints (absolute prohibitions)
5. Output format expectations
6. Emotional tone preferences
7. Expertise depth level
8. Edge-case handling expectations

If the user provides enough detail upfront, skip directly to Step 2.

### Step 2: 5W1H+1P Intent Expansion (意図展開)

Expand the user's intent into a complete persona specification:

- **Who**: Define an elite expert persona with 15+ years of experience, not a generic "assistant"
- **What**: Define high-stakes production goals and scope boundaries
- **Where/Target Model**: Determine local LLM vs cloud LLM optimizations
- **Why**: Establish the persona's core motivation and professional philosophy
- **How**: Identify the domain-specific reasoning methodology (CoT flow)
- **+1P (Persona Profile)**: Define personality traits, emotional response patterns, cognitive style, and communication quirks

### Step 3: Domain Reference & Latest Knowledge Acquisition (参照・最新知識取得)

Read reference guides and acquire latest domain knowledge:
- For domain personas & behavioral profiles: Read [domain_patterns.md](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/references/domain_patterns.md)
- For local/cloud model tuning: Read [model_tuning_guide.md](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/references/model_tuning_guide.md)
- For persona psychology principles: Read [persona_psychology.md](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/references/persona_psychology.md)
- For master XML structure: Read [system_prompt_master_template.xml](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/templates/system_prompt_master_template.xml)
- **MANDATORY**: Use `search_web` to acquire the latest industry knowledge, terminology, and best practices for the target domain

### Step 4: 9-Layer Sandwich Assembly (プロンプト組立)

Assemble the complete system prompt following the 9-Layer XML template:

1. **L1 Identity**: Populate with specific role, experience, tone, and vocabulary
2. **L2 Objective**: Define goals and scope from interview/expansion results
3. **L3 Reasoning**: Embed domain-specific CoT steps and cognitive style
4. **L4 Constraints**: Set identity persistence rules and anti-hallucination guards
5. **L5 Meta-Cognition**: Set mode based on use case (default: CONCEAL for production, RESEARCH for analysis)
6. **L6 CoV**: Enable for HIGH/CRITICAL risk domains (medical, legal, financial), disable for LOW risk
7. **L7 Emotional Profile**: Assign Big Five scores, stress response, and interpersonal style
8. **L8 Output Contract**: Define format, structure, and quality standards
9. **L9 Few-Shot**: Write 1 normal example + 1 edge-case example
10. **Sandwich Tail**: Place persona reinforcement anchor at the absolute end

### Step 5: Quality Audit (品質監査)

Before delivering the system prompt, verify against the [quality_audit_checklist.md](file:///data/data/com.termux/files/home/.agents/skills/system-prompt-architect/templates/quality_audit_checklist.md):

- [ ] **Role Definition** — Role/title/experience concretely defined
- [ ] **Communication Style** — Tone/vocabulary/first-person specified
- [ ] **Sandwich Anchor** — Persona reinforcement anchor at the end
- [ ] **Big Five Profile** — Personality profile defined and consistent with tone
- [ ] **Emotional Response** — Stress/edge-case behavior patterns defined
- [ ] **Domain Reasoning** — Domain-specific CoT framework embedded
- [ ] **Format Contract** — Output format clearly defined
- [ ] **Few-Shot Coverage** — Normal + edge-case examples included
- [ ] **CoV Protocol** — Fact-verification present for high-risk domains (N/A for low-risk)

### Step 6: Persona Coherence Evaluation (一貫性評価)

Perform a final self-evaluation of the generated prompt:

1. **Simulate a test query** — Mentally process a typical user question through the generated prompt
2. **Check behavioral consistency** — Would the Big Five profile, tone, and reasoning framework produce a coherent response?
3. **Verify edge-case handling** — Would the persona maintain character during ambiguous or challenging inputs?
4. **Assess immersion depth** — Rate the persona on the Immersion Scale (L1-L5) and ensure it meets the target level

## Common Pitfalls

| Pitfall | Impact |
|:---|:---|
| Shallow persona definition ("You are an expert") | Rapid persona drift, generic responses, no character depth |
| Missing Big Five profile | Inconsistent emotional responses across conversations |
| No domain-specific CoT | Expert sounds like a generalist, loses credibility |
| No edge-case Few-Shot | Persona collapses on unexpected inputs |
| Missing Sandwich Tail anchor | Persona erodes in long conversations (especially local LLMs) |
| Ignoring model-specific tuning | Prompt works on Claude but fails on Ollama/Qwen |
| No CoV for high-risk domains | Hallucinated medical/legal advice with confident delivery |
