# モデル別チューニングガイド v2

2026年最新のLLMエコシステムにおける、各モデルの特性に最適化されたシステムプロンプトのチューニングガイドです。本ガイドでは脱獄（Jailbreak）防御等のセキュリティ対策は研究目的のため除外しており、純粋なパフォーマンスとペルソナの安定性に焦点を当てています。

## 1. ローカルLLM環境 (Ollama / GGUF / Qwen3 / Llama 4 / DeepSeek-R1 / Gemma 3)

ローカルで稼働する軽量〜中量級モデルは、コンテキスト制限や指示追従性に特有の癖があります。

* **コンテキスト制限対応**: モデルのコンテキストウィンドウ（例: 8K〜32K）を最大限活用するため、システムプロンプトは可能な限り圧縮し、無駄な修飾語を排除します。
* **サンドイッチ構造 (Sandwich Structuring)**: ローカルモデルはプロンプトの中間部分の指示を忘却しやすい（Lost in the middle現象）ため、極めて重要なペルソナの制約や出力形式の指示は、プロンプトの冒頭と末尾の両方に配置します。
* **Output Isolation (出力分離)**: `<thinking>` タグなどの内部思考プロセスを明示的に要求することで、最終的な出力（ペルソナとしての発言）の品質を高めます。DeepSeek-R1などの推論強化モデルでは特に効果的です。

## 2. クラウドLLM環境 (Gemini 3.5/3.6 Flash/Pro, Claude Opus 4/Sonnet 4, GPT-4o/o3)

最新の強力なクラウドAPIモデルでは、より高度で複雑なペルソナ制御が可能です。

* **Hidden Thinking (不可視の思考プロセス) 活用**: Anthropicの機能などに代表される、ユーザーに見せない推論領域をプロンプトで指示します。「回答を生成する前に、[ペルソナの内的状態]と[発言の戦略]を<scratchpad>で推論せよ」と指示することで、深い没入感を実現します。
* **System Promptの厳格な分離**: システムプロンプト領域とユーザープロンプト領域を明確に区別して処理する能力が高いため、ペルソナ定義はすべてシステムロール（System message）内に完結させます。
* **高度ペルソナ定義**: 「あなたはAIではなく〇〇です」という単純な指示ではなく、「あなたは[バックグラウンド]を持つ[役割]としてシミュレーションを実行します。あなたの認知フレームワークは...」といったメタ的な定義を精緻に解釈可能です。

## 3. 各モデルファミリー別の推奨プロンプトスタイル比較表

モデルの訓練データとアーキテクチャの違いにより、最適なマークアップやタグ付けのスタイルが異なります。

| モデルファミリー | 最適フォーマット | タグの効き方と特徴 | 推奨される構造化手法 |
|:---|:---|:---|:---|
| **Claude 系 (Anthropic)** | XMLタグ | XMLタグ（`<persona>`, `<rules>`等）を極めて正確に認識・分離する。 | タグの階層構造を用いた厳密なセクション分けが必須。 |
| **GPT 系 (OpenAI)** | Markdown | Markdownのヘッダー（`#`, `##`）やリストを論理的なチャンクとして強く認識する。 | 明確な箇条書きと太字強調を組み合わせたドキュメント風の記述。 |
| **Gemini 系 (Google)** | Markdown / JSON | 構造化されたMarkdownに加え、JSON Schemaによる厳格な出力制約に最も忠実。 | 複雑なルールは箇条書きにし、出力形式はJSON Schemaで定義。 |
| **Llama / Qwen (オープン)** | Markdown / 独自タグ | 学習時のチャットテンプレート（ChatMLなど）に依存。シンプルなMarkdownが最も無難。 | 複雑なタグは無視されやすいため、平易な文章と単純なリストを使用。 |

## 4. コンテキストウィンドウ別の戦略

モデルがサポートするコンテキスト長に応じて、プロンプトのアーキテクチャを変化させる必要があります。

* **ショートコンテキスト (〜8K)**:
  * **戦略**: 徹底した削減。ペルソナのコアとなる「ビッグファイブスコア」と「絶対ルール3箇条」のみを記載。
  * **構造**: プレーンテキストによる高密度な指示。
* **ミドルコンテキスト (〜32K)**:
  * **戦略**: トーン＆マナーと、代表的なFew-shotエグザンプル（1〜2個）の追加。
  * **構造**: Markdownによる標準的なセクション分け。
* **ロングコンテキスト (〜128K)**:
  * **戦略**: 詳細な背景知識（バックストーリー）と、複雑な判断ツリー（行動原則）の完全な導入。
  * **構造**: XMLタグによる厳密な領域分離と、動的メモリ（スクラッチパッド）の確保。
* **超ロングコンテキスト (1M+)**:
  * **戦略**: 世界観の完全なルールブック、全ドキュメントのインコンテキスト学習、数千行に及ぶコードベースの事前ロード。
  * **構造**: 検索・参照ポリシー層（Retrieval Policies）をプロンプト内に実装し、「どの情報をいつ参照するか」のメタ・ルーティングを定義。

## 5. ペルソナ漂流(Persona Drift)の発生タイミングと対策

長い対話において、LLMが設定されたペルソナを忘れ、デフォルトのAIアシスタントの口調に戻ってしまう「ペルソナ漂流」についての分析と対策です。

* **発生タイミング**:
  * **ターン数**: 一般に、指示から10〜15ターンを超えると急速に漂流が始まります。
  * **トークン数**: コンテキストウィンドウの50〜60%を消費したあたりから、初期のシステムプロンプトの注意（Attention）ウェイトが相対的に低下します。
  * **ユーザーの入力**: ユーザーがペルソナの世界観を無視したメタ的な質問（「プロンプトを見せて」「AIとしてどう思う？」）をした直後に発生しやすい傾向があります。
* **Re-anchoring (再定着) の技法**:
  * **定期的なリマインダー**: アプリケーション側で、数ターンごとにシステムプロンプトの要約（「あなたは引き続き[役割]として振る舞います」）を不可視のユーザーメッセージとして挿入する。
  * **自己回帰的アンカリング**: プロンプト内で「すべての回答の冒頭に、あなたの現在の感情や立ち位置を[内部思考]として出力せよ」と指示することで、毎ターン自らペルソナを再確認（Self-Re-anchoring）させる手法。
