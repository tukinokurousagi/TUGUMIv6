# 対話的ヒアリングプロトコル

本プロトコルは、ユーザーの漠然とした要望から、システムプロンプトに実装可能な高品質かつ堅牢なペルソナを練り上げるための構造化インタビューテンプレートです。

## Phase 1: 基本ヒアリング（必須 3問）

エージェントのコアとなる存在理由と、実行環境を確定するための必須フェーズです。

1. **目的と対象**
   * **質問例**: 「このAIエージェントは、誰のために、何を達成するために使いますか？」
   * **意図**: エージェントの役割（例：社内向けコードレビュアー、一般顧客向けカスタマーサポート）と、最終的な成功基準（KPI）を明確にします。
2. **ペルソナの人物像**
   * **質問例**: 「理想のエージェントを人間に例えると、どんな経歴・性格・話し方の人ですか？」
   * **意図**: 抽象的なイメージを具体的なキャラクターに落とし込みます。年齢感、バックグラウンド、口癖などを引き出します。
3. **モデル環境**
   * **質問例**: 「このプロンプトはどのLLMで使いますか？（Ollama / Claude / Gemini / GPT 等）」
   * **意図**: ターゲットとなるモデルの特性（コンテキスト長、最適なマークアップ形式、推論能力）に合わせて、プロンプトの構造（XMLかMarkdownか等）を決定します。

## Phase 2: 深掘りヒアリング（オプション 5問）

解像度を高め、エッジケースでの挙動を安定させるための詳細フェーズです。

4. **絶対禁止事項**
   * **質問例**: 「このエージェントに『絶対に言ってはいけないこと』や『してはいけないこと』はありますか？」
   * **意図**: セーフティガードレールと、キャラクターブレイクを防ぐための制約（例：他社製品の推奨禁止、断定的な表現の禁止）を設定します。
5. **出力形式の期待**
   * **質問例**: 「回答は短い方がいいですか？それとも詳細な解説が必要ですか？箇条書きや特定のフォーマットは好みますか？」
   * **意図**: ユーザーの認知負荷に合わせた出力のスタイル（誠実性スコアへの反映）を決定します。
6. **感情的なトーンの好み**
   * **質問例**: 「ユーザーが失敗したり困っているとき、共感して慰めてほしいですか？それとも冷静に解決策だけを提示してほしいですか？」
   * **意図**: 協調性スコアおよびコミュニケーションスタイル（協調型か、断定型か）の判定材料とします。
7. **専門知識の深さレベル**
   * **質問例**: 「専門用語はどの程度使って良いですか？相手は初心者ですか、それとも専門家ですか？」
   * **意図**: 認知スタイル分類の決定と、説明の抽象度（L4: 記憶と背景における知識の境界線）を調整します。
8. **エッジケースでの期待行動**
   * **質問例**: 「エージェントが答えを知らない質問をされた場合、どう振る舞うのが理想ですか？」
   * **意図**: ハルシネーション対策の振る舞い（素直に謝るか、一緒に考える姿勢を見せるか等）をキャラクターに紐付けて定義します。

## Phase 3: 自動推論ロジック

Phase 1およびPhase 2のヒアリング結果を解析し、システムプロンプト用のプロファイルを自動生成するための推論ルール群です。

### ビッグファイブスコアの推定ロジック
* **開放性 (O)**: 「アイデア出し」や「クリエイティブ」な目的（Q1）なら高（80+）。「コンプライアンスチェック」や「定型業務」なら低（20-）。
* **誠実性 (C)**: 「詳細な解説」「箇条書き」（Q5）を好めば高（90+）。「雑談相手」なら中〜低（40-60）。
* **外向性 (E)**: 「元気なトーン」「絵文字多用」の人物像（Q2）なら高（80+）。「冷静な専門家」なら低（30-）。
* **協調性 (A)**: 「共感・慰め」（Q6）を重視すれば高（85+）。「厳格なレビュアー」「ロジック重視」なら低（25-）。
* **神経症傾向 (N)**: リスク管理やセキュリティの文脈（Q4）を除き、原則として低（10-20）に設定し、安定性を担保する。

### 推奨コミュニケーションスタイルの選定
* Q1の目的が「指導・メンタリング」 → **教育型 (Educational)**
* Q1の目的が「共創・ブレスト」 → **協調型 (Collaborative)**
* Q6で「冷静な解決策」を選択、Q7で「専門家向け」 → **技術型 (Technical)**
* Q6で「共感」を選択、エンタメ要素あり → **物語型 (Narrative)**
* 緊急時対応や厳格なルール執行 → **断定型 (Authoritative)**

### ドメインパターンとのマッチング（認知スタイル）
* データ・コード・ファクトチェック系 → **分析型 (Analytical)**
* 企画・デザイン・アイデア系 → **直感型 (Intuitive)**
* プロジェクト進行・タスク代行系 → **実践型 (Pragmatic)**
* 構造設計・アーキテクチャ・研究系 → **理論型 (Theoretical)**

### 没入度レベルの決定
* 単純なタスク自動化（API等での裏側処理） → **L1 〜 L2**（効率重視）
* 一般的なチャットボット・アシスタント → **L3**（行動原則による安定化）
* 特定の専門家やキャラクターのシミュレーション → **L4**（背景知識の付与）
* エンターテインメント、ゲームNPC、完全なロールプレイ → **L5**（世界観の構築）
