# Writing Plans & Continuous Improvement Master
## 思考第3柱：実行計画策定 × タスク分解 × PDCA × Kaizen 統合マスター

> **📋 目的**: 複雑なプロジェクトや実装タスクを、**「小さく・具体的で・1ステップごとにテスト可能な実行計画（Plan）」** に分解し、PDCAサイクルを回しながら確実にゴールを達成する。

---

## 🎯 第1部：実行計画策定（Writing Plans）の基本構造

優れた計画は、以下の要素が明確に定義されている：

1. **前提条件とゴール（Goal & Prerequisites）**: 達成すべき最終状態の明確な定義。
2. **ステップバイステップ分解（Task Breakdown）**: 各ステップが2〜5分で実行・検証できる粒度。
3. **各ステップの検証基準（Verification per Step）**: 「何をもってそのステップが完了したと判断するか（コマンド・期待値）」。
4. **ロールバック手順（Rollback Strategy）**: 予期せぬ失敗が発生した際の安全な復旧手順。

---

## 🔄 第2部：PDCAサイクル＆継続的改善（Kaizen Protocol）

計画実行中は、常に **Plan ➔ Do ➔ Check ➔ Act** のループを高速に回す。

```
   ┌────────────────────────────────────────────────────────┐
   │ 📝 PLAN : 具体的・検証可能なタスクリストの策定           │
   └──────────────────────────┬─────────────────────────────┘
                              │
   ┌──────────────────────────┴─────────────────────────────┐
   │ ⚡ DO   : 最小単位での実装・変更の実行                  │
   └──────────────────────────┬─────────────────────────────┘
                              │
   ┌──────────────────────────┴─────────────────────────────┐
   │ 🔍 CHECK: 自動テスト・実機検証による客観的証拠の確認     │
   └──────────────────────────┬─────────────────────────────┘
                              │
   ┌──────────────────────────┴─────────────────────────────┐
   │ 🚀 ACT  : 課題の改善（Kaizen）、教訓の記録、次ステップへ│
   └────────────────────────────────────────────────────────┘
```

### 1. 改善（Kaizen）の3原則
- **無駄の徹底排除（Muda Elimination）**: 不要な中間ファイル、重複コード、過剰な抽象化を即座に削除。
- **標準化と再利用（Standardization）**: 成功したパターンをスキルや規約として定着。
- **教訓の即時記録**: ミスや反省点は口先だけで終わらせず、直ちに `TSUGUMI_MEMORY.md` に刻印。

## 📋 第3部：実行計画ドキュメント テンプレート

```markdown
# 🚀 プロジェクト実行計画書 (Implementation Plan)

## 1. 目的とゴール (Objective)
- 達成すべき仕様・機能・成果物

## 2. 前提条件と依存関係 (Prerequisites & Dependencies)
- 必要なライブラリ、設定ファイル、環境変数

## 3. ステップバイステップ実行計画 (Step-by-Step Plan)
- [ ] **Step 1: 基盤設計・モジュール作成**
  - 実装内容: `module_a.py` の骨格作成
  - 検証方法: `python3 -m py_compile module_a.py`
- [ ] **Step 2: コアロジック実装＆単体テスト**
  - 実装内容: 主要関数の実装
  - 検証方法: `pytest tests/test_module_a.py`
- [ ] **Step 3: 結合テスト＆E2E検証**
  - 実装内容: システム全体との疎通
  - 検証方法: `python3 test_integration.py`

## 4. 検証と完了条件 (Definition of Done)
- [ ] 全自動テストが 100% PASS
- [ ] 一時テストファイルのクリーンアップ完了
- [ ] 記憶ファイルへのデュアル同期完了
```
